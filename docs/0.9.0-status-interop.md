# 0.9.0 status interop: noun-direct status is canonical

DECISION (Samuel, 2026-07-06): at the 0.9.0 engine import, machine status
adopts the NEW engine's shape — the per-noun `<Noun> is currently in Status`
fact type, generated at compile and absorbed by RMAP onto the governed noun's
table — and the SM-instance status metamodel retires.

## Why the shapes differ

The old metamodel keys status by State Machine instance
(`State_Machine_is_currently_in_Status`) and derives per-resource status
through the SM-for-Resource role chain, because — per its own comment in
`readings/core/instances.md` — "Resource is an abstract noun so RMAP cannot
absorb the status into a Resource cell — there IS no Resource cell."

The new engine dissolves that pressure instead of working around it: status
is generated per GOVERNED NOUN (`smDef`, with subtype players routed through
the `governedBy` closure), so the absorbing table always exists. status(e)
is the entity's transition-fold (whitepaper Prop. onestep); the guarded
transition advances the column in the SAME commit chain as the trigger fact
(Def. derive puts transition rules outside the monotone F_S, so the
overwrite is authorized where an ordinary functional assert would collapse
the row). Both metamodels verbalize identically — "is currently in Status" —
so this is a keying change, not a vocabulary change.

## What retires (WITH the import, not before — the old engine runs this
## metamodel until the swap)

- `readings/core/instances.md`: the `State Machine is currently in Status`
  fact type + its exactly-one UC; the `Resource is currently in Status`
  declaration + at-most-one UC; the app-level projection readings
  ("Resource is currently in Status iff some State Machine is for that
  Resource and that State Machine is currently in that Status", e.g.
  `apps/tasks/readings/app.md`).
- The old engine's SM implementation is replaced wholesale by the import:
  `crates/arest/src/compile.rs` (SM seed / s0 trio), `command.rs`
  (transition encoding), `evaluate.rs` (event fold), `ingest.rs`, `check.rs`
  — ~330 of the 433 `currently_in_Status` references live here and vanish
  with the files.

## The new shape, for reference

- `status_facts` (compile pipeline, before layout): each governed noun gets
  `"<Noun> is currently in Status." / "Each <Noun> is currently in at most
  one Status."` through the ordinary reading path (names compiled, never
  concatenated) + the `smStatusFt <noun, ft>` marker.
- RMAP absorbs the functional fact type as a column on the noun's table;
  the machine reads it via `ftpop_absorbed` and overwrites it via
  `row_overwrite` inside the trigger's commit chain (`bs_spop` /
  `bs_commit_m` in the canonical AST — what the Rust kernel runs).
- Reads: `ft_view` / the `query` verb (column-aware for status fact types),
  `actions`, `process_table` (the run queue as a view), `moore_view`.
- A governed trigger without its status column RAISES — a machine without
  its status fact type is an incomplete model, not a fallback case.
